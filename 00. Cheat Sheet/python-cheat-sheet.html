  3. Curly braces outside an f-string make a set or a dict.✗ input({f"Title: "}) ✓ input(f"Title: ") ✗ {"_id"} ✓ {"_id": 501} ✗ params={"q": {title}} ✓ params={"q": title}

25Instance methods & self

class Book:
    def __init__(self, title, pages):
        self.title = title
        self.pages = pages

    def is_long(self):  # aligned with __init__
        return self.pages > 300

book = Book("The Hobbit", 310)
print(book.pages)       # attribute → 310
print(book.is_long())   # call method → True

check = book.is_long    # method, not its result
print(check())          # call it later → True

A method is a function defined in a class. Calling book.is_long() supplies book as self automatically. self.pages reads that book’s page count. Both def lines belong inside the class; neither method belongs inside the other.

26Return a comparison

# Two ways to write the same method:
class Book:
    def __init__(self, pages):
        self.pages = pages

    def is_long(self):
        if self.pages > 300:
            return True
        else:
            return False

    def is_long_short(self):
        return self.pages > 300

print(Book(300).is_long())        # False
print(Book(301).is_long_short())  # True

The comparison already produces a boolean. Returning it directly is equivalent to the full if/else. A simplification suggestion from the editor does not mean the longer version is wrong. Without a return on the false path, that path would return None.

28Mutable defaults: shared list

class BadTeam:
    def __init__(self, name, members=[]):
        self.name = name
        self.members = members

    def add_member(self, name):
        self.members.append(name)

red = BadTeam("Red")
blue = BadTeam("Blue")
red.add_member("Anna")
print(blue.members)                 # ["Anna"]
print(red.members is blue.members)  # True

A default argument is evaluated once when the function is defined, not once per call. Both teams reuse the same default list. append changes it in place. The usual fix is a None default and creating a fresh list inside __init__ when no list was supplied.

29Inheritance & super()

class Animal:
    def __init__(self, name):
        self.name = name

    def make_sound(self) -> str:
        return "some animal sound"

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed

dog = Dog("Rex", "terrier")
print(dog.name)          # Rex
print(dog.make_sound())  # some animal sound

Dog is a subclass of Animal: a dog is an animal. super() reuses the next implementation in the method resolution order; here that is Animal. If Dog defines no __init__, it inherits the base initializer. Writing a new __init__ does not automatically call the base one.

30Override & extend a method

class Employee:
    def get_information(self) -> str:
        return "Employee information"

class Developer(Employee):
    def get_information(self) -> str:
        base = super().get_information()
        return base + " - Role: Developer"

employee = Employee()
developer = Developer()
print(employee.get_information())
print(developer.get_information())

Defining the same method name in a subclass overrides the inherited version. super() lets the override reuse it. -> str declares the intended return type; it does not convert the result. Calling the method on an Employee still uses Employee’s implementation.

31Change state & raise an error

class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount < 0 or amount > self.balance:
            raise ValueError("Invalid withdrawal")
        self.balance -= amount

account = BankAccount("Anna", 100)
account.deposit(50)
account.withdraw(20)
print(account.balance)  # 130

Check before changing state. -= subtracts and saves; = -amount replaces the balance with a negative value. raise signals failure; return ValueError would only return the exception class. These methods change the object and return None. This small example validates withdrawals only.

32Polymorphism & duck typing

class Printer:
    def display_status(self):
        return "Printer ready"

class Screen:
    def display_status(self):
        return "Screen on"

things = [Printer(), Screen()]
for thing in things:
    print(thing.display_status())

One call, different implementations: polymorphism. Duck typing means this code relies on the supported operation, not a shared base class. Python tries the call; an object without the method would raise AttributeError. No custom __init__ is needed here.

33Inherited setup, overridden method

class Document:
    def __init__(self, title):
        self.title = title

    def describe(self) -> str:
        return f"Document: {self.title}"

class PDFDocument(Document):
    def describe(self) -> str:
        return f"PDF: {self.title}"

docs = [Document("Notes"), PDFDocument("Guide")]
for doc in docs:
    print(doc.describe())

PDFDocument inherits the title setup because it defines no __init__. It overrides describe instead. self.title reads the stored title; self.title = ... would change it. Returning a string describes the object without changing its state.

34pass, return & optional __init__

class User:
    pass

class AdminUser(User):
    pass

admin = AdminUser()  # an instance

def example():
    pass             # do nothing; continue
    return "Hello"   # exit; send a value back

print(example())     # Hello

pass fills an otherwise empty block. return exits a function; a bare return gives None. __init__ supplies custom setup and is not required in every class. An empty subclass inherits its initializer; an empty override would skip the inherited setup unless it calls super().

35isinstance: type relationships

class Animal:
    pass

class Dog(Animal):
    pass

pet = Dog()
print(isinstance(pet, Dog))     # True
print(isinstance(pet, Animal))  # True
print(isinstance(pet, str))     # False
print(type(pet) is Animal)      # False

isinstance checks the class and its base classes. type(obj) is SomeClass tests the exact type. is compares object identity; it does not test an inheritance relationship.

36__str__: readable objects

class Book:
    def __init__(self, title):
        self.title = title

    def __str__(self) -> str:
        return f"Book: {self.title}"

book = Book("The Hobbit")
print(book)        # Book: The Hobbit
text = str(book)
print(type(text))  # <class 'str'>

__str__ supplies the readable text used by str(obj) and print(obj). Return a string; do not just print inside the method. Without a custom implementation, a plain object normally displays a class name and an identifier-like address.

37Composition: HAS-A

class Teacher:
    def __init__(self, name):
        self.name = name

class Course:
    def __init__(self, title, teacher):
        self.title = title
        self.teacher = teacher

teacher = Teacher("Anna")
course = Course("Python", teacher)
print(course.teacher.name)  # Anna

A Course HAS-A Teacher: store an object in an attribute. A Course is not a Teacher, so inheritance is not the relationship here. Follow the references: course → teacher → name. Inheritance instead models IS-A, such as Dog IS-A Animal.

38SQLite · query patterns

-- DB Browser: Open Database → your_database.db → Execute SQL
-- Run one complete query with the ▶ button.

-- Choose columns from a table
SELECT column_a, column_b
FROM table_name;

-- Filter rows: compare a column to a value
SELECT *
FROM table_name
WHERE category = 'value';

-- One value can match either choice
WHERE category IN ('value_a', 'value_b');

-- Group OR conditions before adding AND
WHERE (category = 'value_a' OR category = 'value_b')
  AND amount > 100;

-- Rename a result column; calculate without changing data
SELECT name, unit_price * quantity AS total_value
FROM table_name
WHERE quantity > 0
ORDER BY total_value DESC;

-- Sort then select a range of results
SELECT *
FROM table_name
ORDER BY amount ASC
LIMIT 5 OFFSET 5;

-- _ means exactly one character in LIKE
WHERE first_name LIKE '____';

These are patterns, not answers to a particular database. Replace table_name and column names with names from Database Structure. 40find, find_one & count

# find(filter) → a cursor: loop over it, each document is a dict
for book in books.find({"genre": "Fantasy"}):
    print(book["title"], book["year"])

# Several keys in one filter = AND
books.find({"genre": "Fantasy", "in_stock": True})

# find_one(filter) → ONE dict, or None if nothing matches
book = books.find_one({"title": "Dune"})
if book:
    print(book["author"])          # read it, don't loop over it

# count_documents(filter) → an int.  {} = every document
n = books.count_documents({"genre": "Sci-fi"})
all_books = list(books.find())     # cursor → list

find gives many documents, so you loop. find_one gives one dict, so a for loop over it walks its keys, not documents. count_documents always needs a filter; {} means all. A filter is always key: value pairs, so {"_id"} (a set) is not a filter.

# year <= 1950               {"year": {"$lte": 1950}}
# genre != 'Horror'          {"genre": {"$ne": "Horror"}}
# genre IN ('A', 'B')        {"genre": {"$in": ["A", "B"]}}
# isbn IS NOT NULL           {"isbn": {"$exists": True}}

# Range: two operators on the same field
books.find({"pages": {"$gte": 200, "$lte": 400}})

# OR: a list of complete filters
books.find({"$or": [{"genre": "Poetry"}, {"pages": {"$lt": 100}}]})

# Dates: compare with datetime objects, not strings
from datetime import datetime
books.find({"added": {"$lt": datetime(2026, 1, 1)}})

The operator goes inside the field's value: {field: {"$op": value}}. $or is the exception: it sits at the top and takes a list of filters.

Specify a query ↗

42Filter vs projection: two dicts

for book in books.find(
    {"genre": "Fantasy"},                 # 1st = FILTER:     which documents?
    {"title": 1, "year": 1, "_id": 0},    # 2nd = PROJECTION: which fields?
):
    print(book)       # {'title': ..., 'year': ...}  (no _id)

books.find({}, {"_id": 0})                # every doc, every field except _id

Filter ≈ WHERE, projection ≈ the columns after SELECT. Projection: all 1s = only these fields, all 0s = everything except these; don't mix (only "_id": 0 may join the 1s). A value like "Fantasy" never goes in the projection, and 1 in a filter means "equals the number 1".

The second dict means something different per method: projection in find/find_one, the change ($set …) in update_one/update_many. count_documents takes only a filter.

43Arrays & nested documents

# One document:
# {"title": "Dune", "tags": ["classic", "space"],
#  "publisher": {"name": "Chilton", "city": "Philadelphia"},
#  "reviews": [{"user": "kim", "stars": 5}, {"user": "lee", "stars": 3}]}

# In a FILTER, dot notation reaches inside
books.find({"tags": "classic"})                 # list contains "classic"
books.find({"publisher.city": "Philadelphia"})  # nested dict
books.find({"reviews.stars": 5})                # any review with 5 stars

# In PYTHON: one [ ] per level, and loop over lists
book = books.find_one({"title": "Dune"})
print(book["publisher"]["city"])
print(len(book["reviews"]))                     # how many in the list
for review in book["reviews"]:
    print(review["user"], review["stars"])

"publisher.city" is only understood by MongoDB, inside a filter or projection. In Python, book["publisher.city"] is a KeyError: write book["publisher"]["city"]. A list of dicts needs a loop, then [ ] on each item.

46Update operators

f = {"title": "Emma"}                                    # which documents?
books.update_one(f, {"$set": {"year": 1815}})            # set a field
books.update_one(f, {"$inc": {"copies": -1}})            # add / subtract
books.update_one(f, {"$push": {"tags": "romance"}})      # append (duplicates ok)
books.update_one(f, {"$addToSet": {"tags": "romance"}})  # append only if missing
books.update_one(f, {"$unset": {"isbn": ""}})            # remove a field

result = books.update_many({"genre": "Poetry"}, {"$set": {"shelf": "P"}})
print(result.matched_count, result.modified_count)

# upsert: no match → insert a whole new document
books.update_one({"title": "Beowulf"}, {"$set": {"year": 1000}}, upsert=True)

update_one(filter, change). The change must use an operator: a plain {"year": 1815} raises an error. update_many returns one result object, so don't loop over it. upsert creates a new document when nothing matches; it does not add items to a list (that's $push / $addToSet).

52Path & query parameters

# Path parameter: /books/3   ({ } in the route)
@app.get("/books/{book_id}")
def get_book(book_id: int):            # "abc" → 422 automatically
    return find_book(book_id)

# Query parameters: /books?author=tolkien&year=1937
@app.get("/books")
def search_books(author: str | None = None, year: int | None = None):
    result = books                     # start with everything
    if author:
        result = [b for b in result if author.lower() in b["author"].lower()]
    if year:
        result = [b for b in result if b["year"] == year]
    return result                      # the filtered list, not books

A name in { } in the route is a path parameter; every other function parameter is a query parameter. str | None = None: type str or None, default None. Without = None it's required. Inside a function, only use names from its def line or ones you created there.

53Body: POST, PUT, PATCH, DELETE

class Book(BaseModel):                 # every field required (POST, PUT)
    title: str
    author: str
    year: int

class BookUpdate(BaseModel):           # every field optional (PATCH)
    title: str | None = None
    author: str | None = None
    year: int | None = None

def find_book(book_id: int):           # plain helper, no @app line
    for book in books:
        if book["id"] == book_id:
            return book
    raise HTTPException(status_code=404, detail="book not found")

@app.post("/books", status_code=201)
def create_book(book: Book):
    new_id = max((b["id"] for b in books), default=0) + 1
    new_book = {"id": new_id, **book.model_dump()}
    books.append(new_book)
    return new_book

@app.put("/books/{book_id}")           # replace every field
def replace_book(book_id: int, updated: Book):
    existing = find_book(book_id)
    existing["title"] = updated.title  # dict uses [ ], Pydantic object uses .
    existing["author"] = updated.author
    existing["year"] = updated.year
    return existing

@app.patch("/books/{book_id}")         # change only the fields sent
def patch_book(book_id: int, changes: BookUpdate):
    existing = find_book(book_id)
    existing.update(changes.model_dump(exclude_unset=True))
    return existing

@app.delete("/books/{book_id}", status_code=204)
def delete_book(book_id: int):
    existing = find_book(book_id)
    books.remove(existing)             # 204 = no body, nothing to return

A Pydantic class describes the body the client sends; query parameters never need one. model_dump() turns it into a normal dict; exclude_unset=True keeps only the fields the client actually sent. Close the path string before the next argument: "/books/{book_id}", status_code=204.

56Select columns & rows

books["title"]                     # one column → Series
books[["title", "year"]]           # several → DataFrame (a list inside [ ])
cols = ["title", "year"]
books[cols]                        # cols is already a list: single [ ]

books.loc[3, "title"]              # by index LABEL and column name
books.iloc[0]                      # by POSITION: first row
books.iloc[-1]                     # last row
books.iloc[:5, :2]                 # first 5 rows, first 2 columns

old_fantasy = books[(books["genre"] == "Fantasy") & (books["year"] < 1950)]
books[(books["genre"] == "Poetry") | (books["pages"] < 100)]
books[~books["genre"].isin(["Horror", "Crime"])]    # ~ = not
books[books["year"].between(1900, 1999)]            # both ends included
books.loc[books["pages"] > 500, ["title", "pages"]] # rows + columns at once

57Clean & save it back

# Each method returns a NEW object: chain the steps, then save it back
books["genre"] = books["genre"].str.strip().str.lower()

price_clean = books["price"].str.replace(" kr", "")   # part of the text
price_clean = price_clean.str.replace(",", ".")       # build on price_clean
books["price"] = price_clean.astype(float)            # save into the table

books["genre"] = books["genre"].replace({"sci fi": "sci-fi"})  # whole values

books = books.drop_duplicates()            # drop on the TABLE, save back
books = books.dropna(subset=["title"])     # drop rows missing a title
books["genre"] = books["genre"].fillna("unknown")
books = books.drop(columns=["notes"])

# where keeps values where True; mask replaces values where True
books["pages"] = books["pages"].mask(books["pages"] == 0)   # 0 → NaN
books["year"] = books["year"].where(books["year"].between(1450, 2026))

Left side of = decides what you overwrite: books["price"] = … changes one column, books = … replaces the whole table. .str.replace changes part of a text; .replace({…}) swaps whole values. Running a cleaning line without saving it changes nothing.

61strftime codes

from datetime import datetime
